# Code map and publication checklist

## Current dependency chain

```text
config.py
  ├── fisica2corpos.py
  ├── fisica3corpos.py
  ├── preparar_dataset.py
  └── geradorDataset.py  --> physics modules + preparar_dataset.py

MISSING: saturn2.py (shared Torch numerical / normalization routines)
  ├── saturn3.py  [three-body] + config.py constants through its imported module
  ├── saturn3b.py [two-body] + config.py
  ├── diagnostico.py [three-body] + saturn3.py for compatible checkpoints
  └── diagnostico2C.py [two-body] + saturn3b.py
```

All nine scripts are temporarily kept in the repository root to preserve relative imports. Moving them into nested modules **without revising imports, hard-coded paths and checkpoint loading** would break the research workflow.

## Research variants and caveats

- `saturn3.py`: three-body model; its comments identify state input `(B,18)` and masses `(B,3)`.
- `saturn3b.py`: two-body model; its implementation uses `(B,12)` and masses `(B,2)` despite historical naming/comments.
- `diagnostico.py`: expects `saturn2.py` and may import `saturn3.py` to load body-token checkpoints.
- `diagnostico2C.py`: expects `saturn2.py` and imports `saturn3b.py`.
- `geradorDataset.py`: hard-coded `selecao = 0` means three-body generation unless manually changed.
- NPZ trajectories generated by the script contain a time column, while training code slices physical coordinates and velocities.
- Historical comments, references to older checkpoint types and copied documentation are kept as-is; they need future manual review, not automatic rewriting.
- Diagnostic scripts have some legacy names/comments; verify model/checkpoint selection before interpreting figures.

## Before publishing publicly

1. Get permission for sharing research code, data and results; check any collaborator and third-party contributions.
2. Ensure no tokens, passwords, credentials or personal data appear in *any Git commit*, including history.
3. Add the missing shared module, then validate training/evaluation separately.
4. Create a small controlled demo; do not commit all training trajectories or large checkpoints.
5. Save and document selected diagnostic images in `results/`.
6. Add a license only after reuse rights are confirmed.

## Legacy Transformer module added

`saturn2.py` contains the three-body temporal-window Transformer (`RedeTransformer`), dataset loaders, Yoshida integration, physical loss terms, autoregressive rollout and a training entry point. It was reconstructed from a Markdown paste; verify it against the original `.py` before training. Its `RedeTransformer` constructor references `escalaDelta` as a global although the training code assigns it locally inside `if __name__ == '__main__'`; this must be resolved before instantiation. The two-body diagnostics' use of this legacy three-body class also requires compatibility checks.
